# 검증 기록

검증일: 2026-10-25 (한국시간)

## 현재 방식

GitHub 예약 수집·자동 커밋·사용자 정의 배포 워크플로를 삭제했습니다. 현재는 사이트의 **설교 목록 불러오기** 버튼이 사용자의 브라우저에서 공식 목록과 상세 HTML을 직접 수집합니다. 갱신에 재배포가 필요하지 않습니다. 검증된 결과는 해당 브라우저의 localStorage에 저장됩니다. 자동 폴링도 제거했습니다.

## 실제 환경 검증

- 공식 5개 목록 및 상세 페이지, robots.txt, 이용약관 확인.
- 공식 사이트의 CORS 허용 헤더 확인. 공개 사이트 origin에서 robots.txt를 직접 fetch하여 HTTP 200과 본문 읽기 성공.
- 새 브라우저 크롤러의 실제 버튼 실행 성공: 공식 메타데이터 URL 29회 요청, 고유 설교 1,370편 / 출처 항목 1,458개 확인. 신규 0·수정 0.
- 실제 브라우저 수집 결과 전체를 Python `validate_archive`로 독립 검증: 식별자·내용 해시·정규화·교차 분류 일관성 모두 통과.
- 전체 최초 수집의 날짜 범위: 2013-12-15 ~ 2026-10-23. 현재 원문 해석 실패는 분류 항목 13개(고유 12편)로 본문 미기재·원본 오타·부분 절이며 그대로 보존.

- 공개 사이트에서 실제 버튼 크롤링 성공. 확인 시각이 기본 07:04:01 KST에서 07:33:48 KST로 갱신되고, 재방문 후에도 유지됨. 새로 배포하지 않은 상태에서 검색 데이터 갱신을 확인.
- 공개 사이트 Chromium: 본문 검색 3편, 브라우저 저장본 복원, JavaScript 오류 없음. WebKit 모바일: 버튼·화면 정상.
- 공개 index.html 및 sermons.json이 로컬 검증본과 바이트 단위로 일치. Pages는 codex/pages 브랜치의 정적 파일을 게시하며 사용자 정의 워크플로는 없음.

## 자동 테스트

| 검사 | 결과 |
| --- | --- |
| Python 파서·수집·안전 저장 | 28개 통과 |
| JavaScript 검색·정규화·CSV·5만 건 성능 | 8개 통과 |
| Chromium/WebKit, 1440·390·320px 검색 화면 | 84항목 통과 |
| Chromium/WebKit 수동 수집·저장·정책·취소 | 66항목 통과 |

수동 수집 테스트는 다음을 확인합니다.

- 버튼을 누르기 전에는 공식 사이트 요청이 없고, 10분을 진행해도 자동 수집하지 않음.
- 신규 1건 및 제목 수정 1건을 가져와 필터를 유지한 채 즉시 화면에 반영.
- 새 데이터의 전체 JSON을 Python으로 재검증.
- 페이지를 다시 열어도 브라우저 저장본 유지.
- 403·robots 금지·약관 변경·HTML 변경·페이지 수 급감 시 화면과 저장본 보존.
- 취소 시 기존 저장본 보존.
- 과거 전체 확인에서 전체 93페이지를 순회하고 검증한 뒤 반영.
- 저장 공간 부족 시 현재 화면은 갱신하고 저장 실패를 알리며 이전 저장본 보존.
- robots의 허용/금지 우선순위·와일드카드·요청 간격 처리.
- 5개 분류의 실제 HTML fixture를 브라우저와 Python에서 파싱한 결과와 내용 해시 일치.
- 모바일 가로 넘침 및 JavaScript 오류 없음.

CSV는 UTF-8 BOM·CRLF·따옴표/쉼표 이스케이프·수식 시작 문자 처리와 실제 브라우저 다운로드 바이트를 검증했습니다. Excel 데스크톱 앱에서 직접 열기, 실제 iOS/Android 기기의 터치 동작은 미검증입니다.

## 이전 방식의 이력

이전 GitHub runner 방식에서는 Linux x64·Linux ARM·macOS 모두 공식 사이트 TCP 연결 시간 초과가 발생했습니다. 해당 예약/수집 워크플로는 현재 삭제했고 이를 해결해야 사이트를 쓸 수 있는 구조가 아닙니다. 현재는 방문자의 네트워크에서 버튼으로 직접 수집합니다. 원본의 접근 제한이나 브라우저 허용 정책이 변경되면 기존 데이터를 유지하고 오류를 표시합니다.
