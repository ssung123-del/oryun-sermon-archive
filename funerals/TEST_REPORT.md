# 장례소식 분석 페이지 검증

검증일: 2026-11-25 (한국시간)

## 실제 데이터 확인

- 공식 교우소식 menu=247의 전체 177페이지 확인.
- 장례 공지 1,741건, 게시일 2020-04-03~2026-11-25.
- 교구 표기 정상 1,642건, 미분류 86건, 일부 미분류 13건. 확인되지 않은 표기는 임의 배정하지 않음.
- 장례 분류가 빠진 과거 제목과 본문 내부에 섞인 빈 목록 태그를 확인하고 처리. 옛 실제 HTML(64·163페이지)을 Chromium과 Python에서 파싱한 결과 일치.
- 상세 공지 `mode=view&bid=...`가 오래된 공지의 실제 원문을 여는 것을 확인. 목록의 bid만으로는 과거 공지가 열리지 않아 상세 URL로 연결함.
- 이름·연락처·장소·제목·본문을 JSON/CSV에 저장하지 않음. 허용된 일곱 필드 외에는 검증 실패 처리.
- robots와 약관 확인 후 요청 간격을 지켜 수집. 접근 제한 우회·미디어 다운로드·별도 서버 사용 없음.

## 테스트

- Python 장례소식 테스트 7개 통과: 복수 교구, 같은 교구 중복 제거, 상속 표기, 원문 명시 교구만 사용, 장례 공지만 선택, 날짜/구조/건수 오류, 개인 정보 필드 거부, 잘못된 저장 시 원본 유지.
- JavaScript 분석 테스트 7개 통과: 기간/교구/유형 복합 필터, 월 경계·0건인 월, 연관 집계/분할 집계, 미분류 배분, CSV BOM/CRLF/수식 처리, 실제 전체 데이터 검증, Python 추출 결과 일치.
- Chromium/WebKit × 1440·390·320px의 168항목 통과: 통계·필터·차트 클릭·표·페이지 이동·CSV 다운로드·날짜 오류·수동 수집·브라우저 저장·재방문 복원·실패/취소 시 보존·자동 요청 없음·가로 넘침 없음.
- 실제 브라우저 수집 성공: 정책 2회+목록 1회, 총 3요청, 로컬 실측 약 3.3초. 결과 전체를 Python 검증기로 독립 검증.
- 기존 프로젝트를 포함한 Python 테스트 35개 및 JavaScript 테스트 15개 통과.

실제 네트워크 속도는 사이트 응답과 이용자의 환경에 따라 달라집니다.

## 해석상 한계

공지 1건을 단위로 분석합니다. 실제 사망자 수/사망률을 계산하지 않습니다. 가족·복수 교구가 한 공지에 있거나 동일 사건이 별도 공지로 반복되면 실제 사건 수와 다를 수 있습니다. 개인 식별을 통한 사건 병합은 하지 않습니다.

교구 인원·교구 개편/이관 이력과 정확한 장례일이 없으므로 규모 보정, 개편 전후 동일 교구 통합, 실제 소천일 분석은 하지 않습니다. 분석의 시간축은 게시일이며 부분 월/연도에 주의해야 합니다.

Excel 앱에서 직접 열기와 실제 iOS/Android 기기의 터치 검증은 미실시입니다. CSV 바이트와 Chromium/WebKit 반응형 동작으로 확인했습니다.
