# 오륜 장례소식 분석

공식 교우소식에서 장례 공지만 추려 게시일·교구별로 분석하는 별도 정적 페이지입니다. 설교 검색기는 그대로 유지합니다.

공개 주소: <https://ssung123-del.github.io/oryun-sermon-archive/funerals/>

## 데이터와 집계 기준

- 출처: <https://oryun.org/life/?menu=247>
- 최초 공개 목록 177페이지를 확인했습니다. 장례 분류와, 분류 태그가 없는 과거 글 중 장례 구분 및 소천·별세가 명시된 제목을 사용합니다.
- 초기 데이터는 2020-04-03~2026-11-25의 장례 공지 1,741건입니다.
- 저장 필드는 공지 ID, 게시일, 교구/공동체 표기, 장례 구분, 분석 상태, 미분류 표기 수, 공식 원문 URL뿐입니다. 이름·연락처·장소·제목·본문은 저장하지 않습니다.
- 통계는 **장례 공지 건수**입니다. 실제 사망자 수, 유가족 수, 교구 인원 대비 사망률이 아닙니다. 동일 사건이 별도 ID로 다시 게시되었는지는 개인 정보 없이 확정할 수 없어 자동으로 합치지 않습니다.
- 게시일 기준입니다. 실제 소천일·발인일을 분석한 것이 아닙니다. 연도 양 끝의 부분 기간과 교구 규모 차이를 고려해야 합니다.
- 제목의 명시적인 대괄호 표기에서만 교구를 읽습니다. 원문에 표기가 없거나 확인할 수 없는 경우 추정하지 않고 미분류로 남깁니다.
- ‘거마위’, ‘그레이스부’ 등 확인된 원문 표기를 그대로 사용합니다. 과거 이름과 현재 이름을 임의로 통합하지 않습니다. ‘거마위’와 ‘거여마천위례’는 자동 합치지 않습니다.
- 한 공지에 여러 교구가 나오면 **연관 집계**는 교구마다 각각 1건을 셉니다. 교구별 합계가 공지 수보다 클 수 있습니다.
- **분할 집계**는 한 공지를 교구 표기 수로 나누어 배분합니다. 예: 두 교구면 각각 0.5건입니다. 식별되지 않은 표기도 그 수만큼 미분류에 배분합니다.
- 월별 추이와 총 공지 수는 복수 교구와 관계없이 ID당 1건입니다. 달력월 평균은 선택한 월 수로 나누며 0건인 월과 부분 월도 포함합니다.

## 화면 기능

기간·교구/공동체·장례 구분 필터, 최근 12개월/올해/전체 기간, 교구별 막대그래프, 월별 추이, 교구×월 비교표, 원문 링크와 페이지 이동을 제공합니다. 막대 클릭으로 해당 교구나 월을 선택할 수 있습니다. 집계/목록 CSV는 UTF-8 BOM과 CRLF를 사용합니다.

기본 분석 기간은 최근 12개 달력월입니다. 전체 자료를 보려면 **전체 기간**을 누르세요. 교구 개편과 불완전한 표기는 미분류 카드와 원문을 함께 확인하세요. 분석 기간은 성능을 위해 20년 이하로 선택합니다.

## 갱신 방식

- **최신 소식 불러오기**는 브라우저에서 robots.txt, 이용약관, 최신 목록을 직접 확인합니다. 신규 게시물이 한 페이지를 넘으면 기존 식별자를 만날 때까지 다음 페이지로 이어갑니다.
- 변경이 없으면 정책 2회 + 목록 1회로 보통 3회 요청입니다. 과거 공지의 수정은 **과거 전체도 확인**에서 확인합니다.
- 검증 완료 후에만 화면과 이 브라우저의 localStorage를 바꿉니다. 취소·연결 오류·구조 변경·비정상 감소 시 기존 목록을 유지합니다.
- 갱신에 재배포나 GitHub 자동화가 필요하지 않습니다. 브라우저를 닫아도 저장본을 다시 사용할 수 있지만 다른 기기와 공유되지는 않습니다.
- 최소 1.2초 간격으로 한 요청씩 보냅니다. robots의 요청 간격/빈도 지시, 재시도와 타임아웃을 적용합니다. 약관 변경이나 접근 제한은 우회하지 않습니다.
- 공식 사이트의 CORS 허용이 바뀌거나 네트워크에서 차단되면 버튼 수집은 실패할 수 있습니다. 기본 분석 자료는 유지됩니다.

## 로컬 실행과 관리

프로젝트 루트에서:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

<http://localhost:8000/funerals/>로 엽니다. 운영은 index.html과 notices.json만 필요합니다.

Python으로 기본 파일을 수동 갱신할 때:

```sh
source .venv/bin/activate
python funerals/scraper.py --incremental
python funerals/scraper.py  # 과거 전체 재확인
```

Python 수집기는 루트 requirements.txt의 requests/BeautifulSoup와 기존 수집 정책 도우미를 사용합니다. 전체 검증 뒤 원자적으로 JSON을 저장합니다. 실패 시 `.crawl-state.json`의 개인 정보 없는 페이지별 메타데이터로 1시간 이내 재시작을 지원합니다. 최신 목록 식별자/전체 페이지 수가 달라지면 재사용하지 않습니다. 체크포인트가 손상되면 삭제한 뒤 다시 실행하세요. 이 파일은 Git에 포함하지 않습니다.

## 테스트

```sh
python -m unittest discover -s tests -p 'test_funerals.py' -v
node --test tests/funerals-core.test.cjs
node tests/funerals-browser.cjs
```

브라우저 테스트는 개발용 Playwright와 Chromium/WebKit이 필요합니다. 공개 배포 파일에는 라이브러리나 Python 코드를 포함하지 않습니다. 상세 결과는 [검증 기록](TEST_REPORT.md)에 정리합니다.
